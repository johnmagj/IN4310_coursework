Lec. 7.: Performance evaluation

- Dataset splits: Train set, validation set, and test set. All subset of the original dataset/samples

- k-fold cross validation: 1. We combine the train and validation sets into one large training subset. 
			2. Then these are split into k folds (subsets), using k-1 folds to train and 1 fold for validation
			3. The folds used for training is used as a typical train set, for say regression, or in DNN where we spit it up into batches and do epochs
			4. Repeated k times

- Development data vs application data: Data used for development might be to "clean" or standardized compared to what the model will meet in real application
	- Called domain shift
	- Use of external dataset (to represent "real world" data) (should only be use once) to evaluate the final model. Doing to much optimization in regard of the model will overfit to this test data.

Lec. 8.: Data Augmentation

- Data augmentation: Image transformations to produce more data from what we have

- Image transformations:
	- Geometric: changes size, shape, position, orientation
		- Affine: rotations and flips, shifting, scaling, and shearing

	- Photometric: changes brightness, contrast, colour, noise
		- Colour jitter: Random values of the HSV cylinder (hue, saturation, value)
		- Solarization: colours above a certain threshold are inverted

	- Blur transformation: Using a Gaussian kernel (reduce/down-scale corners more => lowering value of kernel weights)

	- Mixup: overlap two images, does not need to be 50/50, one could be stronger
	- Cutmix: take a random section (say a square a toward bottom right corner) from one image and paste in into (overlap) another image, producing a collage

	- both above techniques the labels might as well be blended, so if the resulting image of an augmented image is of what we consider 40% label A and 60% label B, we can say the new label is: 0.4 A and 0.6 B. Using softmax that would simply be [0.4, 0.6].

- Label smoothing: Instead of one-hot encoded (hard) labels like [0, 1, 0], we smooth them with softmax-like probability, like
[0.05, 0.90, 0.05]


- Augmentation technique must be chosen based on the data, some techniques might be counter productive causing critical information loss like colour of flags (if turned grayscale) or other characteristics of the data

- Global pooling: used before the dense layer at the end of the network allows for use of use of different image sizes,
	- Pool one value from each feature map at this point, creating an 1D array

- Random weight initialization: normal or uniform distribution with mean zero

- Contrastive Learning:
	- Similarity score: different augmentations of the same images have higher score, and augmentations from different images lower score

Lec. 9.: Recurrent Neural Networks - RNNs

- In short:

- Architecture: Hidden state vector should have same length as the embedding vector or longer

- Embedding size/dimension: The features of the word/token
- Context window: The meaning of the sequence

- Pipeline: A body of text (words) is converted into tokens (tokenization) based on the vocabulary and divided into sequences, all with the same size (number of tokens, for efficient computing). If not the seq. is padded or truncated to fit the RNN architecture. This is effectively the context window. A batch is a collection of these sequences. All the tokens in each sequence have a token ID (defined in the vocabulary). Then for each token we have an embedding (defined in the vocabulary). The embeddings have a given length/dimension/number-of-elements, i.e. a vector (typically horizontal for consistency) where each element is abstract feature. The number of tokens/embeddings per sequence define the number of timesteps/width of the RNN. A batch consisting of multiple sequences are sent as input to the RNN, and we can think of RNN being cloned over as many floors as there are sequences in the batch (batch size). Each floor having the same parameters/weights as all the other. Then each sequence is processed at its own floor. Loss is calculated for each timestep (not only the last), essentially predicting the next word/token for each word/token in the sequence. We get an average loss per floor, and per batch, which after the forward pass is used to train/update the weights. The embedding matrix (holding all the embeddings, one for each token) is also updated since the process of turning a token ID into an embedding can be considered an matrix multiplication (a one hot token ID vector multiplied with the embedding matrix), thus differentiable and the embedding values are trained through back propagation.
START (simple 1 layer RNN, 1 hidden state (network detph): Input embedding vector multiplied by first weight matrix --> hidden state block where incomming hidden state from previous timestep is multiplied by hidden state matrix before added to the input result and a bias, this expression is then sent into an activation function to create the hidden state --> this hidden state is then multiplied with the output matrix and adding a bias before going through an activation function to produce the output for the timestep. Serialy run per "floor" (sequence), need first token/word of each sequance to get an intial hidden state, which is nessecary for the second timestep.

- Since no activation after the first matric multiplication with the input embedding vector and weight matrix, there are no matematical need for adding a bias, this bias would be absorbed into the bias of the hidden state calcualtion due to linearity. However, because of computational efficiency PyTorch uses two biases.

- teacher forcing: We predict the next token for each timestep and calculate the loss, but does not use the prediction for the next time step, we use the true token for that timestep as in the input sequence

- Stateful RNNs: The last hidden state of one chunk is passe on to the start of the next chunk. Seqs. and batches are split so that succeeding sequences are processed on the same "floor" of the RNN, thus the last hidden state of one seq. can be sent to the first time step on the same floor for the next batch.

- Types:
	One-to-one (like normal FFNN). One input, one output --> classification or regression
	One-to-many: E.g. One image input, a sequence of words as output --> image captioning
	Many-to-one: E.g. Series of words/characters input, a sentiment category as output --> sentiment analysis
	Many-to-many: E.g. A sequence of words input, a category for each word as output --> par of speech/grammatically tagging
	Many-to-many(encoder-decoder): E.g. neural machine translation (NMT), input and output can have different lengths

- The output is a 1D-vector of same size as the vocabulary size, where each element correspond to a token/word in the vocabulary. This is ran through a softmax function so that we get a probability distribution of what the predicted token/word for this timestep.
- No need for positional encoding in classical RNNs, the timesteps are the positions, and the calculations are sequential (in contrast to transformers that calculate in parallel and thus need information about the positions)

- Exploding gradient problem:
	- Approaches to deal with it:
		- Clipping by value: Set all elements: g_i > T, to g_i = T. PROBLEM that we lose direction
		- Clipping by norm (scaling): If l2-norm of G > T, scale all elements g_i by T/l2(G), this PRESERVES direction

- LSTM (Long-Short-Term-Memory): Solve the vanishing gradient problem. Exploding gradient still possible, but here we have strategies like above

Lec. 10: Vision Transformers	

- Word embedding: Turing a word into an array of numbers. The array length (also called dimensionality) is a hyperparameter typically 300-500 elements. The numbers are the weights of the embedding layer, typically a normalized number between -1 and 1.
	- Thus these word embeddings become vectors in an embedding space
	- Initialized randomly (normal or uniform), if not from another train model. Sometimes scaled on in specific ways based on vocabulary size and embedding dimensions
	- Updated (trained) after every iteration (not epoch), but words not included in an iteration not updated
- Positional encoding: A vector describing where a given instance of a word appears (the position) in a text string. This is added to the word embedding vector. Calculated through various sin and cos functions.
- Vocabulary: A table of the words/tokens, their ID, and then the corresponding embedding/vector

- The pipeline from sentence to vectors:
	1. Sentence of words are turn into sequence of token IDs
	2. Each token ID is converted into its respective word embedding
	3. The position of each word is found and concatenated at the end of the word embedding
	
- Context window: The length/window of text that the model can see/work with. I.e. number of tokens to be embedded and positionally encoded with positions within the window.

Lec. 11: Deep Learning Theory

- Entropy: 
	High --> highly probable state
	Low --> less probable state
	Microstate: Configurations
	Macrostate: Grouping of microstates

	No randomness --> unlikely --> low entropy
	High randomness (maximum 50/50) --> typical --> high entropy

	= Average amount of surprise (total surprise divided by number of event) = expected surprise of event = the entropy of the event

	Entropy = expected value of surprise

- A mathematical metric (the abstract generalization of distance (in analysis)):
	- Satisfies four criteria:
		d : X * X --> R

		1. d(x, y) >= 0
		2. d(x, y) = 0 <=> x = y
		3. d(x, y) = d(y, x)
		4. d(x, z) <= d(x, y) + d(y, z), the triangle inequality

- Mutual information: reduction in uncertainty in Z = X + Y, when knowing something about X, but nothing about Y
	- BUT: something that never changes can't tell us anything about something that do

- Surprise: Inversely related to probability (but not directly, see bellow)
	Low surprise --> something highly probable happened
	High surprise --> something unprobeable happened 

	surprise(X) = log(1/p(X))
	For two outputs we use log with base 2

	Average amount of surprise (total surprise divided by number of event) = expected surprise of event = the entropy of the event
	Entropy = expected value of surprise
